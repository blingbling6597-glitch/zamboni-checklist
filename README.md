# 洗冰檢點表電子化

冰上樂園洗冰指揮官(值班)作業安全防護檢點表的電子化專案。同仁用手機網頁填寫，資料存進 Google 試算表，試算表就是統計分析後台。

## 填寫規則

每次營運時段洗冰，四個角色**各自**用手機勾自己的項目，最後由**值班洗冰指揮官覆核並簽認**。

| 符號 | 意思 |
| --- | --- |
| ✅ | 單項有正確執行 |
| 📐 | 單項不熟，但現場提醒後有執行 |
| ❌ | 單項沒執行，或溝通提醒後仍無正確執行（**必須填原因**） |

- 每一項都要勾，不可空白；沒勾完或 ❌ 沒寫原因，系統不讓送出，並用紅框標出缺的題目。
- 「場次」= 洗冰日期＋整點時間（例如 `2026-11-24 14:00`）。四個人選同一個日期和整點，資料就會歸在同一場。
- 指揮官覆核時，畫面會帶出四個角色的自評結果，只要改不正確的項目。被改過的項目會標示「已修正（自評：…）」，後台也會統計。
- 覆核簽認後，該場次就鎖定，角色不能再改。角色還沒到齊也可以先簽認，系統會先提醒。

## 運作方式

```
各角色手機網頁自評 ─┐
                    ├─▶ 試算表「明細」（一題一列）─▶「場次」（一場一列，狀態：待填寫／待覆核／已覆核）
指揮官手機網頁覆核 ─┘                                   │
                                                         ▼
                        總覽／項目分析／人員分析／❌原因紀錄／趨勢分析／時段分析（公式即時更新）
```

統計一律用**最終結果**：已覆核的用指揮官的結果，還沒覆核的先用自評結果。

| 分頁 | 內容 |
| --- | --- |
| 總覽 | 場次數（已覆核／待覆核／待填寫）、✅正確率、📐提醒後執行率、❌未執行率、重點項目、近 7 天、本月；尚未完成的場次；最需要加強的 10 項；最近 10 場 |
| 項目分析 | 48 項各自的 ✅📐❌ 次數與比例、覆核修正次數，可篩選角色、階段、重點；堆疊長條圖 |
| 人員分析 | 每位同仁的 ✅📐❌、正確率、被覆核修正次數；依角色拆開；重點項目；各人需加強的項目 |
| ❌原因紀錄 | 所有 ❌ 的場次、人員、項目和原因 |
| 趨勢分析 | 每日／每週／每月的 ✅📐❌ 與正確率、每月 × 角色；圖表 |
| 時段分析 | 各整點時段、時段 × 角色、星期別 |
| 場次 | 一場一列：四位人員、狀態、覆核者、✅📐❌、❌項目與原因、覆核意見 |
| 明細 | 一題一列的長表：自評結果／原因、覆核結果／原因、最終結果，所有分析的來源 |
| 人員名單 | 網頁姓名選單的來源 |

## 安裝步驟（約 15 分鐘）

1. 在 Google 雲端硬碟新增一份空白 **Google 試算表**，命名例如「洗冰檢點後台」。
2. 選單 **擴充功能 → Apps Script**。
3. 在 Apps Script 編輯器，把 `apps-script/` 裡的檔案逐一建好：
   - 預設的 `程式碼.gs` 改名為 `Config`，內容換成 `Config.js`。
   - 「＋ → 指令碼」新增 `Core`、`Code`、`Analysis`，分別貼上同名 `.js` 的內容。
   - 「＋ → HTML」新增 `Index`，貼上 `Index.html` 的內容。
   - 左側「專案設定」勾選「在編輯器中顯示 appsscript.json」，把內容換成 `appsscript.json`（台北時區）。
   - 按儲存。
4. 回到試算表重新整理，上方會出現 **「洗冰檢點」** 選單，按 **① 初始化**。第一次會要求授權，用你的帳號同意。
5. 在「人員名單」分頁的 A 欄填入所有同仁姓名，一格一人。
6. 回 Apps Script 編輯器，按右上 **部署 → 新增部署作業**：
   - 類型：**網頁應用程式**
   - 執行身分：**我**
   - 存取權：公司 Google Workspace 選「**機構內任何人**」；個人 Gmail 只能選「**任何人**」（知道網址就能填，網址不要外流）
   - 按「部署」。
7. 回試算表按 **洗冰檢點 → 顯示填寫網址**。把網址傳到群組，或做成 QR Code 貼在洗冰室。

> 之後如果修改了程式，要到「部署 → 管理部署作業 → 編輯 → 版本選『新版本』」再部署，網址不會變。

## 手機操作

**各角色：** 開網址 → 選洗冰日期、整點時間、角色、姓名（第二次起會記住角色和姓名）→ **開始檢點** → 每一項勾 ✅／📐／❌（❌ 要寫原因）→ **送出**。中途關掉網頁不會丟失已勾的內容。

**指揮官：** 先照上面勾完自己的項目，再按 **前往覆核簽認**（或首頁選指揮官角色後按 **指揮官覆核簽認**）→ 選場次 → 檢查並修正四個角色的結果 → 寫覆核意見（選填）→ 勾「已確認」→ **覆核簽認**。

## 日常維護

| 情況 | 做法 |
| --- | --- |
| 人員異動 | 直接改「人員名單」分頁，網頁會即時讀取 |
| 忘了網址 | **洗冰檢點 → 顯示填寫網址** |
| 手動改過「明細」 | **重算場次彙總** |
| 分析分頁被改壞 | **重建分析分頁** |
| 資料量很大（約一年以上） | 每年把舊的「明細」「場次」另存一份試算表封存，再清空 |

## 表單改版（例如 11509-2 → 下一版）

1. 修改 `apps-script/Config.js`：
   - `FORM_VERSION` 改成新版號。
   - 題目文字沒變或只修錯字 → **保留原編號**，跨版本統計才能接起來。
   - 新增題目 → 給新編號。
   - 刪除題目 → **不要刪掉那一行**，加上 `retired: true`。
2. 貼回 Apps Script，重新部署新版本，再按 **重建分析分頁**。網址不變，舊資料保留，「明細」的「表單版本」欄可以區分新舊版。

## 目錄

| 路徑 | 說明 |
| --- | --- |
| `原始表單/` | 紙本表單原檔（Excel、PDF）。改版時直接覆蓋並 commit，用 git 歷史比對差異 |
| `apps-script/Config.js` | 題目設定（由原始 Excel 產生，48 題，18 個重點） |
| `apps-script/Core.js` | 檢查完整性、產生明細列、套用覆核、場次彙總的純邏輯 |
| `apps-script/Code.js` | 試算表選單、網頁入口、網頁呼叫的後端 API |
| `apps-script/Index.html` | 手機填寫與覆核網頁 |
| `apps-script/Analysis.js` | 建立分析分頁與圖表 |
| `tests/core.test.js` | 核心邏輯測試：`node --test tests/core.test.js` |
